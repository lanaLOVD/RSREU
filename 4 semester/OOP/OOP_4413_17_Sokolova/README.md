## Описание игры

Mario — аркадный платформер в стиле пустыни. Игрок управляет ковбоем, который бежит по процедурно генерируемому миру, собирает монеты и прыгает на скорпионов. Игровые объекты (скорпионы, монеты) постоянно находятся в движении. Мир генерируется бесконечно по мере продвижения игрока.

---

## Управление

| Клавиша | Действие |
|---|---|
| `←` / `A` | Движение влево |
| `→` / `D` | Движение вправо |
| `Пробел` / `W` | Прыжок |
| `Shift` | Бег (скорость ×1.8) |

---

## Уровни сложности

| Уровень | Описание |
|---|---|
| Лёгкий | Мало врагов, медленные скорпионы, больше монет |
| Средний | Стандартные настройки |
| Тяжёлый | Много врагов, быстрые скорпионы |

## Структура проекта

Проект реализован по паттерну **Модель-Вид-Контроллер (MVC)**:

```
OOP_4413_17_Sokolova/
├── main.cpp
├── CMakeLists.txt
├── controller/
│   ├── MenuController.h / .cpp   — контроллер главного меню
│   ├── GameController.h / .cpp   — контроллер игрового процесса
│   └── AboutController.h / .cpp  — контроллер окна "Об игре"
├── view/
│   ├── MenuView.h / .cpp         — главное меню
│   ├── GameView.h / .cpp         — игровой экран
│   └── AboutWindow.h / .cpp      — окно "Об игре / Управление"
└── model/
    ├── GameObject.h / .cpp       — базовый класс игрового объекта
    ├── Player.h / .cpp           — игрок
    ├── Enemy.h / .cpp            — враг (скорпион)
    ├── Coin.h / .cpp             — монета
    ├── Platform.h / .cpp         — платформа
    └── GameModel.h / .cpp        — игровая модель (логика, генерация мира)
```

## Иерархия классов и отношения

- **Наследование:** `Player`, `Enemy`, `Coin`, `Platform` наследуют от `GameObject`
- **Композиция:** `GameModel` владеет коллекциями `Platform`, `Enemy`, `Coin` и объектом `Player` через `unique_ptr`
- **Агрегация:** `GameController` использует `GameModel` и `GameView`
- **Ассоциация:** `GameController` хранит указатель на `MenuController` для возврата в меню после окончания игры


## Требования к программе (выполнены)

- Глобальные переменные не используются
- Все поля классов закрытые (`private`)
- Типы и классы FLTK используются только в классах View
- `void*` передаётся только в статических callback-функциях для интеграции с FLTK
- Callback устанавливает тот класс, чей метод вызывается
- После окончания игры программа возвращается в главное меню (без пересоздания окна)
- Динамические данные (`new`) минимизированы; используются `unique_ptr` для автоматического управления памятью
- Классы модели не знают про классы View
- Классы View не знают про классы контроллера
